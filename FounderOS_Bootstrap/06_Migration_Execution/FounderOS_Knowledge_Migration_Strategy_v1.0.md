# FounderOS Knowledge Migration Strategy Specification v1.0

## Document Status

Version: v1.0\
Layer: Migration & Execution Specification

------------------------------------------------------------------------

# 1. Purpose

This document defines how FounderOS transforms existing information
assets into structured intelligence.

The migration system must:

-   preserve original knowledge
-   create structured knowledge objects
-   maintain historical context
-   establish relationships
-   prepare Hermes-ready intelligence

The objective is not to move files.

The objective is:

> Convert accumulated founder experience into reusable FounderOS
> intelligence.

------------------------------------------------------------------------

# 2. Migration Philosophy

## Principle 1 --- Preserve Before Transform

Original information remains unchanged.

Migration creates:

    Original Source

    +

    Structured Intelligence Layer

------------------------------------------------------------------------

## Principle 2 --- Quality Over Quantity

Do not migrate everything.

Prioritize:

-   decisions
-   principles
-   architecture
-   lessons
-   validated research

------------------------------------------------------------------------

## Principle 3 --- Preserve Context

Knowledge without context loses value.

Important migration records should preserve:

-   background
-   alternatives
-   reasoning
-   outcome
-   lessons learned

------------------------------------------------------------------------

# 9. Migration Validation

After migration, FounderOS should answer:

## Founder Context

-   What are my operating principles?
-   How do I make decisions?
-   What projects am I pursuing?

## Project Context

-   What is this project?
-   Why was it created?
-   What decisions were made?
-   What is next?

## Decision Context

-   Why did we choose this?
-   What alternatives existed?
-   What happened afterward?

Use review workflow.
