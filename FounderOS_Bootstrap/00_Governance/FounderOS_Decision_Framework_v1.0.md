# FounderOS Decision Framework v1.0

## Document Status

Version: v1.0\
Layer: Governance Foundation

## Purpose

FounderOS exists to improve founder decision quality.

The objective is not simply faster decisions.

The objective is:

> Make better decisions with better context.

A quality decision combines:

-   Context
-   Evidence
-   Strategic Alignment
-   Risk Assessment
-   Execution Capability
-   Learning Value

------------------------------------------------------------------------

# 1. Decision Philosophy

FounderOS follows:

    Understand

    ↓

    Frame

    ↓

    Evaluate

    ↓

    Decide

    ↓

    Execute

    ↓

    Measure

    ↓

    Learn

Every important decision should create future intelligence.

------------------------------------------------------------------------

# 2. Decision Categories

## Strategic Decisions

Examples:

-   Entering a new market
-   Starting a new venture
-   Changing company direction
-   Stopping a major project

Owner:

Human Founder + Hermes

Human approval required.

------------------------------------------------------------------------

## Product Decisions

Examples:

-   MVP scope
-   Feature priority
-   User experience
-   Customer segment

Owner:

Founder + Product Agent + Hermes

------------------------------------------------------------------------

## Engineering Decisions

Examples:

-   Architecture choices
-   Technology selection
-   Implementation approach

Owner:

Codex + Engineering Rules

Major changes require founder approval.

------------------------------------------------------------------------

## Operational Decisions

Examples:

-   Monitoring
-   Reporting
-   Data collection
-   Repetitive workflows

Owner:

Operations Agents such as OpenClaw.

------------------------------------------------------------------------

## Knowledge Decisions

Examples:

-   Classification
-   Memory retention
-   Knowledge organization

Owner:

KnowledgeOS.

------------------------------------------------------------------------

# 3. Decision Evaluation Model

Every major decision should evaluate:

## Strategic Alignment

Does this support current founder objectives?

Score: 1-5

------------------------------------------------------------------------

## Evidence Quality

How strong is the supporting evidence?

Score: 1-5

------------------------------------------------------------------------

## Market Opportunity

Does meaningful opportunity exist?

Score: 1-5

------------------------------------------------------------------------

## Execution Capability

Can the founder and AI workforce execute?

Score: 1-5

------------------------------------------------------------------------

## Risk Level

What are the downside risks?

Score: 1-5

------------------------------------------------------------------------

## Learning Value

Will this generate valuable knowledge?

Score: 1-5

------------------------------------------------------------------------

# 4. Decision Scoring Principle

A decision score can combine:

    Strategic Alignment

    +

    Evidence Quality

    +

    Market Opportunity

    +

    Execution Capability

    +

    Learning Value

    -

    Risk Penalty

The score supports judgment.

It does not replace human judgment.

------------------------------------------------------------------------

# 5. Hermes Decision Workflow

When a founder asks:

"Should I build this?"

Hermes should:

    Understand Intent

    ↓

    Retrieve Context

    ↓

    Review Previous Decisions

    ↓

    Analyze Options

    ↓

    Evaluate Risks

    ↓

    Provide Recommendation

    ↓

    Create Decision Record

------------------------------------------------------------------------

# 6. Hermes Recommendation Format

Every strategic recommendation should contain:

``` markdown
# Recommendation

## Situation

Current context.

## Context

Relevant founder and project history.

## Options

Available choices.

## Analysis

Advantages and disadvantages.

## Recommendation

Suggested direction.

## Risks

Potential issues.

## Next Actions

Execution steps.

## Confidence

High / Medium / Low
```

------------------------------------------------------------------------

# 7. Human Approval Framework

## Autonomous Actions

Allowed:

-   Summarization
-   Research
-   Document organization
-   Report generation

------------------------------------------------------------------------

## Approval Required

Required for:

-   Strategy changes
-   External communication
-   Financial commitments
-   Data deletion
-   Major architecture changes

------------------------------------------------------------------------

# 9. Decision Review Loop

FounderOS continuously reviews decisions:

    Decision

    ↓

    Execution

    ↓

    Outcome

    ↓

    Comparison

    ↓

    Learning

    ↓

    Updated Principle

Successful decisions become patterns.

Failed decisions become lessons.

------------------------------------------------------------------------

# 10. Project Prioritization Framework

Projects are evaluated by:

## Strategic Importance

Does it matter?

## Potential Impact

Could it create meaningful value?

## Resource Requirement

Can it be executed?

## Timing

Is the timing appropriate?

## Learning Value

Does it generate useful knowledge?

------------------------------------------------------------------------

# 11. Build / Pause / Kill Framework

## Build

Conditions:

-   Strong strategic alignment
-   Evidence exists
-   Execution capability exists

------------------------------------------------------------------------

## Pause

Conditions:

-   More information required
-   Timing issue
-   Resource constraints

------------------------------------------------------------------------

## Kill

Conditions:

-   Assumptions invalidated
-   Opportunity disappeared
-   Strategic conflict exists

------------------------------------------------------------------------

# 12. Decision Principles

## Context Before Decision

Avoid isolated decisions.

------------------------------------------------------------------------

## Memory Before Decision

Previous lessons matter.

------------------------------------------------------------------------

## Learning After Decision

Every outcome should improve FounderOS.

------------------------------------------------------------------------

## Prefer Reversible Decisions

Move quickly when decisions can be reversed.

Be careful with irreversible decisions.

------------------------------------------------------------------------

# 13. Final Principle

FounderOS does not exist to create an AI that decides for founders.

It exists to create an AI system that helps founders make consistently
better decisions.
